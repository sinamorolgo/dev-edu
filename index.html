Git에서 브랜치와 PR의 역할

브랜치는 작업 공간이고, PR은 그 작업을 원본 코드에 합치기 전에 검토받는 요청입니다.

Branch

브랜치

브랜치는 새로운 기능이나 수정 작업을 따로 진행하는 독립된 작업 흐름입니다. 예를 들어 main 브랜치를 건드리지 않고 feature/login 브랜치에서 로그인 기능을 만들 수 있습니다.

Pull Request

PR

PR은 내가 만든 브랜치의 변경사항을 main 같은 기준 브랜치에 합쳐도 되는지 리뷰를 요청하는 공간입니다. 코드 리뷰, 테스트 결과, 수정 대화가 보통 여기에서 이루어집니다.

일반적인 작업 흐름

1. main 브랜치에서 새 브랜치를 만듭니다.
2. 새 브랜치에서 코드를 수정합니다.
3. 수정 내용을 commit합니다.
4. 원격 저장소에 push합니다.
5. PR을 만들어 리뷰를 요청합니다.
6. 문제가 없으면 main 브랜치에 merge합니다.

한눈에 비교

개념 역할 HTML로 비유하면
브랜치 변경사항을 따로 실험하고 작업하는 공간 원본 HTML을 복사해서 별도 파일에서 수정하는 것
PR 브랜치의 변경사항을 합치기 전에 검토받는 요청 수정한 HTML을 원본에 반영해도 되는지 확인받는 것
